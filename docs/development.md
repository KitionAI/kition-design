| `docs/` | This guide, [architecture](architecture.md), [gaps](gaps.md), [roadmap](roadmap.md), [quality](quality.md), [attribution](attribution.md), [writing format](writing-format.md); target-app parity in `parity/`, feature notes in `features/` |

## Build and test

```sh
cargo test --workspace
cargo build --release -p kition-design                     # the headless kit executable
cd web && pnpm install && pnpm engine && pnpm test:flow     # the kit's editor
cargo xtask ci                                             # the gate: fmt, clippy, tests, layers, assets, wasm
```

`cargo xtask test` runs the tests with cargo-nextest when it is installed (its settings are in
`.config/nextest.toml`). `cargo xtask help` lists the other tasks.

By default `pnpm install` in `web/` installs the published `@kition/*` packages from npm, at the
versions the committed `web/pnpm-lock.yaml` pins, so the editor needs no other checkout. To work
against local checkouts instead, run `KITION_LINK=1 pnpm install` in `web/`: `web/.pnpmfile.cjs`
then links `@kition/kit-editor`, `@kition/kit-host`, `@kition/kit-ui-protocol` and
`@kition/kit-dev-host` from the kition-sdk checkout and `@kition/tessera-icons` from the
kition-tessera checkout next to this repository (or the ones `KITION_SDK` and `KITION_TESSERA`
name), each one whose package is there. The linked install rewrites `web/pnpm-lock.yaml`; do not
commit that lockfile.

`pnpm engine` (`web/scripts/build-engine.sh`) builds the engine to WebAssembly into
`web/public/engine/` and copies fonts into `web/public/fonts/`. It needs a C compiler for wasm32
(Homebrew's llvm `clang` on macOS) for the engine's C dependencies, and takes the fonts from a
[kition-fonts](https://github.com/KitionAI/kition-fonts) checkout next to this repository (or the
one `KITION_FONTS_DIR` names). `pnpm dev` serves the editor in the development host
(`web/dev.html`); [web/README.md](../web/README.md) describes the editor's folders.

The headless executable also serves the kit's tools to any MCP client through kition-sdk's
`kition-kits-mcp`:

```sh
cargo build --release -p kition-design                 # target/release/kition-design
# in a kition-sdk checkout:
cargo build -p kition-kits --bin kition-kits-mcp
target/debug/kition-kits-mcp --workspace <folder> --kit <kition-design>/target/release/kition-design
```

[agent/guide.md](../agent/guide.md) explains the tools, and [writing-format.md](writing-format.md)
lists every command.

## Take the README screenshots

The pictures under `assets/readme/` are taken by `web/scripts/readme-shots.mjs` on kition-sdk's
shared runner (`tools/readme-shots`): it opens the showcase sample `sales-analytics-dashboard`
from a [kition-showcase](https://github.com/KitionAI/kition-showcase) checkout next to this
repository (or the one `KITION_SHOWCASE` names) in the development host, in Classic display mode
at 1440 × 900 and device scale 2, and changes it only through the editor and the engine's
commands. With the engine built in `web/public/engine/` and no HTTP proxy set:

```sh
cd web
node scripts/readme-shots.mjs              # hero, see-1 … see-4
node scripts/readme-shots.mjs see-2        # only the named ones
```

When `pngquant` is installed the script shrinks each picture with `--quality 70-90` (a README
picture is at most 400 KB). `made-1.png` … `made-4.png` are copies of showcase samples'
`thumb.png`. Every file under `assets/` has a row in [attribution.md](attribution.md)
(`cargo xtask assets`).

## Publish

Kition ships the kit's package, `kition-design-<version>.tgz` (the `design-ui/` folder), a release
asset of this repository tagged `package-v<version>`. It is built on GitHub, never on a developer
machine: the Package workflow (`.github/workflows/package.yml`, which calls Kition's reusable
`kit-package.yml`) builds the commit it is started on, with `gh workflow run package.yml -R
KitionAI/kition-design`, and publishes the Release with the package's lock entry,
`kition-design-<version>.json`. Kition pins it with `node scripts/pin-kits.mjs design` (see
`docs/kits.md` there). A version is published once: bump `version` in `kit.json` to publish a
change.
