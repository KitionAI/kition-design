# UI and interaction parity

> **Last reviewed:** 2026-11-27 · **Last updated:** 2026-11-27 · **Target:** Figma Design UI3 (desktop app 126.10.7)

Fine canvas control is what Figma users feel first: handles, snapping, nudging, modifier keys,
drag behaviour, numeric precision. This checklist covers the tools, gestures and panels, in two
columns:

- **Engine:** the behaviour is built in the engine and checked by its tests (the `*_tests` named in
  the notes), against Figma's documented behaviour or by eye: **done**, **partial**, **missing**.
- **Editor:** a person can do it in the web editor (`web/`, in `web/dev.html`). **done** only where
  a test in `web/tests` does it with real pointer and keys (named in the cell); **partial** where
  such a test covers part of it or the editor lacks part; **not checked** where it is built but no
  hand test does it yet; **missing** where the editor has no way to do it.

The editor's interaction was compared on 2026-11-26 and 27 with the reference editor this one is
built on (a 127-point walkthrough, then the plan's stages 1–11): the keyboard keeps working wherever
a person last clicked, drags follow the pointer (a 348-layer page repaints about 50–80 times a
second while a rectangle is dragged), text, input methods, the system clipboard, dropped files,
ruler guides, auto layout handles and vector editing work by hand. The thirty things a designer
does in the first ten minutes, and six more, run in `web/tests/hand/first-ten-minutes.mjs`: 29 of
the 30 and the 6 more as the reference does them (the one left: a marquee that touches part of a
top-level frame selects nothing); a whole phone login screen takes 101 actions and gets stuck no
time (`web/tests/hand/login.mjs`). Not compared side by side with the running Figma; real devices
(trackpad, input methods, cross-app clipboard) and Kition Desktop's frame are not checked.

**Summary (estimated):** UI/UX fidelity ~60%. Layout and look of UI3 compared side by side (~65%);
the first ten minutes by hand pass (29 of 30).

## Keyboard shortcuts

One keymap (`kition_design_engine::keymap`) drives the menus, the canvas and the shortcuts panel. `crates/engine/engine/src/shortcut_parity_tests.rs` holds one row per
shortcut in the public documentation (the help centre's feature articles: keyboard layouts, text
properties, alignment, frames, components, prototypes, plugins, keyboard navigation…), with the
macOS and Windows/Linux keys, what does it here and a note in our words, and checks every row on
both platforms; rows the documentation is silent on pin today's keys, so every default binding is
in the table.

- **In the editor (2026-11-27):** the counts above are the engine's keymap. Every key the editor's
  Keyboard shortcuts dialog lists was then pressed once in `web/dev.html`, with a rectangle (a text
  for the Text keys, editing it for the keys of text editing) selected, and what reached the engine
  or changed in the editor read back. Three did nothing and were fixed: F6 and Shift+F6 from the
  canvas (`regressions/issue-hand-f6-regions`) and Shift+Space for Preview
  (`regressions/issue-hand-shift-space-preview`); the whiteboard's eight tool keys (Q, B, X, M, U,
  E, W, Shift+Cmd+Enter) work on boards only and are no longer listed in a design file
  (`regressions/issue-hand-shortcuts-board-tools`). The others that showed nothing there need their
  context: V with Move already chosen, H (kit-editor's hand, no engine tool), Alt+1 and Alt+8 with
  that panel already shown, Cmd+Z with nothing to undo, Cmd+Alt+Enter with no frame to present (it
  presents one in `web/tests/hand/first-ten-minutes.mjs` N34). Held keys and gestures (hold Z,
  Space-drag, Alt-hover) are not in that sweep; the hand tests do them.
- **Bound from the documentation:** A for the Frame tool, Shift+' for the pixel grid (Cmd+' kept: the articles
  disagree), Alt+Cmd+\ / Ctrl+Alt+\ for others' cursors (`view.multiplayerCursors`), Ctrl+F6
  to the toolbar on Windows/Linux, Shift+Cmd+U to link text (Cmd+K kept), Cmd/Ctrl+] and [ to
  nest list items while editing (`text.listIndent` / `text.listOutdent`), Cmd/Ctrl+Backspace
  to ungroup, Ctrl+Shift+A / Ctrl+Alt+Shift+A to suggest auto layout, Ctrl+Alt+Cmd+K /
  Ctrl+Alt+Shift+K to go to the main component, the arrows panning the view 64 px (Shift: 320 px) when
  nothing is selected, Control suspending snapping on macOS, and Space, N, C and F while
  presenting. The paint bucket's tooltip shows Shift+B (B still works).
- **Paste:** Shift+Cmd/Ctrl+V (Paste over selection) and Alt+Cmd/Ctrl+V (Paste properties) act
  as bound, on the editor's own copy; Cmd/Ctrl+V reads the system clipboard: an image, SVG text or
  text copied in another app pastes as an image layer, an editable frame or a text layer in the
  middle of the view, layers this editor copied paste as layers (`web/src/menus/clipboard.ts`,
  `web/tests/hand/clipboard.mjs`). Files dropped on the canvas import where they land
  (`web/src/canvas/fileDrop.tsx`).
- **Where the documentation disagrees with itself** (noted per row): pixel grid (Shift+' or
  Cmd+'), letter spacing (Alt or Cmd with < >; Cmd would be the font size keys, Alt bound),
  Windows remove fill (Alt+/ or Alt+,; Alt+, is letter spacing), the Layers panel on Windows (Alt+1
  or Ctrl+1), send to back / bring to front (one table shows only the bracket).
- **Platform keys:** in the editor every Windows/Linux key runs its command, also the eight whose key differs from the Mac's (Alt+Shift+H / V distribute, Ctrl+Alt+Shift+T, Ctrl+Alt+P, Ctrl+Alt+M, Ctrl+Shift+] / [, Ctrl+Alt+Shift+A), which kit-editor's frame, binding the Mac's keys, left without a handler (`web/tests/hand/other-platform-keys.mjs`, the page reporting Linux). macOS rows use Cmd and Option, Windows/Linux rows Ctrl and Alt (tested: no
  macOS glyph on Windows/Linux keycaps, no "Ctrl"/"Alt" words on macOS); no default binding uses a
  chord the system keeps (Cmd+H/M/Q/Tab/Space, Ctrl+Space and the screenshot keys on macOS;
  Alt+Space/Tab/F4, Ctrl+Esc, Ctrl+Alt+Delete and Linux workspace and terminal-switch keys).
- **Keyboard layouts:** keys follow the character typed, named as on a US keyboard. A symbol
  another layout types with Shift (`/` is Shift+7 on a German keyboard) counts without the
  Shift. Not done: per-layout tables like the documentation's (a German Shift+' types `"` and
  reaches Shift+2).
